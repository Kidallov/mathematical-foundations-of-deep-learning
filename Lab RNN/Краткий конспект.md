# RNN: краткий конспект для себя

**Что мы сделали:** обучили небольшую модель читать русские слова слева направо и на каждой позиции угадывать следующее слово. Это не классификатор документов: правильный ответ есть после каждого входного токена.

## Весь путь данных

**Текст → слова → индексы → эмбеддинги → состояния RNN → логиты → вероятности следующего слова.**

Например, «я читаю книгу» превращается в пару:

- вход: `[BOS, я, читаю, книгу]`;
- правильный ответ: `[я, читаю, книгу, EOS]`.

Когда модель прочитала «я читаю», её последняя позиция должна дать высокую вероятность слову «книгу».

## Четыре специальных токена

| Токен | Индекс | Зачем нужен |
|---|---:|---|
| PAD | 0 | Дополнить короткие строки пакета; не входит в потерю |
| UNK | 1 | Заменить реальное слово вне словаря; входит в потерю |
| BOS | 2 | Обозначить начало документа |
| EOS | 3 | Обозначить конец документа и остановить генерацию |

**Запомнить:** PAD — «слова здесь нет», UNK — «слово есть, но его не знает словарь».

## Как работает память

Индекс слова — только номер строки. Embedding выбирает по нему обучаемый вектор из 128 чисел. Это не готовое значение смысла: векторы настраиваются вместе с сетью.

Один рекуррентный слой обновляет память:

$$h_t=\tanh(W_xx_t+U_hh_{t-1}+b_h).$$

- xₜ — признаки текущего слова;
- hₜ₋₁ — память о предыдущих словах;
- hₜ — новая память;
- Wₓ, Uₕ, bₕ — обучаемые параметры, общие для всех позиций.

В нашей сети два слоя: первый обрабатывает эмбеддинг, второй — новое состояние первого слоя на той же позиции. Память начинается с нуля для каждого окна; длина обучающего окна — максимум 32 токена.

## Формы, которые нужно узнавать

| Объект | Форма |
|---|---|
| Вход и цель | (B,T) |
| Эмбеддинги | (B,T,128) |
| Состояния верхнего слоя | (B,T,128) |
| Логиты | (B,T,V) |

B — число фрагментов в пакете, T — длина, V — число токенов словаря. Логиты — ещё не вероятности: это произвольные вещественные оценки. Softmax превращает их в числа от 0 до 1 с суммой 1.

## Как сеть учится

Для правильного следующего слова с вероятностью p ошибка равна **−ln(p)**. Чем выше p, тем меньше ошибка. Ошибки усредняются только по настоящим целям, без PAD.

Один шаг обучения:

1. `zero_grad()` — убрать старые градиенты.
2. Прямой проход — получить логиты и потерю.
3. `backward()` — вычислить производные потери по параметрам через всю развёрнутую цепочку RNN.
4. Ограничить норму градиента, если она слишком велика.
5. `optimizer.step()` — обновить параметры методом AdamW.

Перед `CrossEntropyLoss` не добавляют softmax: он уже учитывается внутри устойчивого вычисления потери.

## Как понять, что получилось

- **Train loss** — ошибка на примерах, по которым обновляются веса.
- **Validation loss** — ошибка на отложенных документах без обновления весов.
- **Ранняя остановка:** если валидация не улучшается три эпохи, остановиться и вернуть лучшие веса.
- **Перплексия:** PPL=exp(loss). Меньше обычно лучше, но только при одинаковых данных, словаре и токенизации. Это не процент ошибок и не точное число кандидатов.
- **Top-k:** k наиболее вероятных следующих токенов после запроса.
- **Жадная генерация:** выбрать argmax, добавить токен к тексту и повторять до EOS или лимита.

Если train loss уменьшается, а validation loss растёт, модель всё лучше подстраивается под обучение без улучшения на отложенных данных — признак переобучения.

## Почему продолжение может быть плохим

Словарь ограничен: редкие слова становятся одним UNK. Частые слова и UNK могут получать большую вероятность, поэтому жадная генерация зацикливается. Кроме того, данных мало, модель маленькая, пунктуация удалена, а контекст ограничен окнами. Низкая потеря по такой задаче ещё не означает связный литературный текст.

RNN трудно удерживать длинные зависимости: градиенты через много шагов могут затухать или взрываться. Ограничение нормы помогает при взрыве, но не решает проблему затухания.

**Фраза для защиты:** «Я реализовал двухслойную Elman RNN вручную, подготовил сдвинутые пары следующего слова, исключил PAD из потери, обучил модель AdamW и выбрал веса по лучшей валидационной кросс-энтропии. Качество оценил перплексией и показал реальные прогнозы, включая ограничения генерации».

## Мои числа из этой работы

- 1 000 обучающих и 200 валидационных документов; словарь 6 004 токена.
- 12 эпох; лучший результат на 12-й: validation loss **4.4570**, PPL **86.23**.
- До обучения PPL была около 6491. Это улучшение численной метрики, а не гарантия хорошего текста.
- 28.77% слов валидации заменены на UNK; генерация часто повторяет его.
- Найдено 47 одинаковых нормализованных префиксов между частями: оценка не полностью независима.
